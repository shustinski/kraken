## Владение файлами

Server владеет исходными и производными файлами проекта. Hub загружает
миниатюры через авторизованный HTTP, проверяя размер и SHA-256. В проверке Hub
Python audit hook запрещал открывать серверные каталоги проекта и создавать
его локальный индекс; окно и pipeline открылись при этом запрете.

Для серверных заданий Contour и NeuralImage используется явный `AssetSource`.
Изображения поступают через `/api/v1/agent/jobs/{job}/inputs/{version}` с
токеном сеанса. Поток проверяется по SHA-256 до передачи декодеру и временно
кэшируется в памяти. Входные пути в staging логические: файлов изображений по
ним нет. Contour получает источник и для просмотра, и для пакетной обработки;
NeuralImage — для датасета и распознавания. ZIP выборки и маски обучения
разбираются в памяти. Пути ZIP, дубликаты, символические ссылки, размеры
изображений и соответствие CIF проверяются.

Локальные временные файлы используются для результатов, опубликованной через
API модели и пакетов исправлений. Это клиентский staging и экспорт, а не
доступ к серверному хранилищу проекта. Публикация результатов и исправлений
выполняется через Server. Самостоятельный режим плагинов с обычными файлами
сохранён.

## Исправленные дефекты

- Серверная миниатюра могла открывать `external_path` на машине Hub. Теперь
  серверный источник всегда читается через API, без постоянной копии входа.
- Contour ожидал существующие входные файлы даже для серверного проекта.
  Добавлен источник потоков в просмотр, LOD и пакетную обработку, включая
  передачу загрузчика между процессами.
- Общий MIME `application/octet-stream` попадал в проверку типов Contour.
  Agent определяет тип по расширению и в режиме потоков, и в файловом режиме.
- NeuralImage не принимал `lossless_binary_png` в параметрах распознавания.
  Поле восстановлено в модели параметров.
- Agent удалял `USERNAME` из окружения; реальный CUDA-тренировщик падал при
  инициализации оптимизатора PyTorch. Необходимые переменные имени пользователя
  сохранены, остальные переменные не передаются без разбора.
- Локальный серверный пользователь не имел связанного Performer, поэтому
  выдача работы была невозможна. Связь создаётся при аутентифицированном
  обращении; существующий Performer сохраняется.
- Повторное прикрепление слоя пыталось создать новый каталог вместо
  повторного использования существующей привязки.
- Ошибка результата плагина терялась в состоянии задания. Сохраняются как
  ошибки протокола, так и сообщение ошибки от Agent.
- Статистика пропускала реальные события возврата/приёмки, считала кандидатов
  исправлений новой векторизацией и не распознавала импорт и бинарное
  представление. Подсчёт приведён к записанным событиям.
- Декодирование числового union обрезало дробные показатели отчёта. Целые
  счётчики и дробные значения теперь сохраняют исходную точность.
- Новая панель анализа пыталась создавать локальное хранилище для серверного
  проекта. Этот доступ устранён; ограничение панели показано явно.

## Покрытие действий интерфейса

Добавлен воспроизводимый приёмочный набор `tests/test_live_ui_workflow.py`.
Он работает с отдельным настоящим HTTP-сервером и PostgreSQL, создаёт собственный
проект на 100 исходных изображениях и управляет настоящими Qt-виджетами через
QTest. В Contour нажимаются кнопки пакетной обработки и сохранения выборки;
в NeuralImage нажимается «Начать», затем «Вернуть модель в Kraken».
Обработчики, обучение, распознавание и публикация результатов не подменяются.
Автоматизирован выбор файлов в системных диалогах и ввод тестовых настроек.
Рисование исправлений вручную заменено возвратом пакета с пятью корректно
изменёнными CIF в каждой из двух групп; импорт и приём выполняются через UI.

Функциональные критерии: завершение заданий, 100 кадров в каждом представлении,
раздельные CIF из исходников и из бинарных изображений, серверный транспорт,
сохранение результатов, работа назначений и сверка статистики. Качество
нейросети и геометрии не является условием прохождения этих проверок.

Во время покрытия исправлены:

- серверное сканирование папки и добавление связанного слоя без проверки
  серверных каталогов через файловую систему клиента;
- восстановление режима «только обучение» и сохранение модели в каталоге
  результатов задания, доступном действию возврата в Kraken;
- выбор бинарного представления при запуске Contour из его узла;
- обновление списка CIF при выборе уже активного изображения;
- выбор новых серверных пользователей в окне назначения ролей;
- возврат из проекта в каталог нажатием на уже выбранный пункт «Проекты».
- проверка выбранной роли для обращений desktop Agent в контексте проекта
  его задания: после назначения ролей обработка не прекращается на heartbeat
  и публикация результата сохраняет правильные проверки доступа.

Для запуска нужен отдельный подготовленный сервер. Переменная
`KRAKEN_UI_TEST_CONFIG` указывает на приватный JSON с полями `server_url`,
`username`, `password`, `source_directory`; исходная папка содержит 100 кадров.

проекта `KRAKEN_UI_REOPEN_PROJECT` указывает на сохранённый тестом `project.json`.
