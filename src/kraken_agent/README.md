# Kraken Agent

## Гарантии очереди и публикаций

Агент атомарно переводит самое старое задание из `queued` в `staging` в транзакции
SQLite. Несколько экземпляров хранилища не могут получить одно задание одновременно.
Серверный воркер запускает только задание текущей аренды.

Запись итогового результата и переход в `importing`, `partial`, `failed` или
`cancelled` выполняются одной транзакцией. Повторная доставка той же публикации
возвращает `duplicate: true` без изменения ревизии, в том числе после завершения
задания. Новая публикация для отменённого или завершённого задания отклоняется.
Успешная обработка остаётся в `importing` до отдельного подтверждения импорта.

При остановке выполняющегося плагина задание получает `recovery_required`.
При новом запуске локального Agent прерванное задание автоматически возвращается
в очередь с сохранёнными параметрами, входами, прогрессом и контрольной точкой.
Готовый результат в `importing` сохраняется и повторно не вычисляется.
Серверный Agent получает эти данные из новой аренды на сервере; локальная
`server-jobs.sqlite3` служит рабочим кешем, а не источником восстановления.
Остановка Agent не переводит серверное задание в ошибку: после окончания аренды
оно доступно следующему Agent. Уже опубликованный на сервере результат
достаточно импортировать без повторного запуска плагина.

## Прогресс и контрольные точки

Agent сохраняет локальный прогресс независимо от Hub. Для серверных проектов
воркер раз в две секунды отправляет изменившееся состояние на сервер отдельным
потоком, не блокирующим heartbeat аренды. При недоступности сервера состояние
остаётся локально до следующей попытки; после потери машины восстанавливается
последнее состояние, подтверждённое сервером.

Плагин атомарно пишет JSON по `KRAKEN_PROGRESS_PATH`, например
`{"job_id":"…","fraction":0.4}`. Также поддерживаются `progress` от 0 до 1
или пара `completed`/`total`.

Для продолжения вычисления плагин атомарно пишет JSON по `KRAKEN_CHECKPOINT_PATH`:

```json
{
  "job_id": "идентификатор текущего задания",
  "state": {"next_batch": 17},
  "files": [
    {
      "relative_path": "checkpoints/model-17.bin",
      "sha256": "SHA-256 файла из 64 строчных шестнадцатеричных символов",
      "size_bytes": 1234
    }
  ]
}
```

Файлы контрольной точки должны находиться под `checkpoints/` в staging;
опубликованные снимки не изменяются. Сначала плагин записывает новые файлы,
затем заменяет JSON. Agent проверяет хеши, передаёт файлы в серверное blob-хранилище
и только после этого сохраняет ссылки на них. Старые аренды не могут читать или
менять сохранённое состояние. Допустимый размер JSON — 1 МиБ.

Перед запуском плагина Agent восстанавливает файлы и передаёт `KRAKEN_RESUME_PATH`
с JSON `{"progress":…, "checkpoint":…}`. Плагин читает своё поле `state` и
продолжает с указанного шага. Без поддержки этого контракта плагином задание
повторно запускается по сохранённому манифесту, а не с середины вычисления.

Для сервера нужна миграция `20261029_0011` (`alembic upgrade head`).

Регрессионные проверки очереди, HTTP callback, отмены и реальных подпроцессов:

```powershell
python -m pytest tests/test_agent_execution_safety.py tests/test_agent_execution_persistence.py -q
```

Локальный агент плагинов. Держит очередь заданий в SQLite и слушает только
loopback. В режиме воркера забирает задания с Kraken Server по отзывному
машинному токену.

Отладка: **Run and Debug** → **Kraken Agent**.

```powershell
uv sync --extra server
uv run kraken-agent --help
```

Токен для режима воркера выпускает `kraken-admin create-agent-token`. Команда
описана в [`kraken_server/README.md`](../kraken_server/README.md).

## Команды

| Параметр | По умолчанию | Пояснение |
|---|---|---|
| `--data-dir` | `%USERPROFILE%\.kraken\agent` или `KRAKEN_AGENT_DATA` | Каталог очереди и промежуточных файлов |
| `--host` | `127.0.0.1` | Только loopback: `127.0.0.1` или `::1` |
| `--port` | `0` | Порт контрольного HTTP. `0` — выбрать свободный |
| `--token` | случайный | Одноразовый токен локального управления. Если не задан, агент генерирует его сам |
| `--plugins-config` | нет | JSON-реестр «операция → команда». В режиме воркера обязателен |
| `--connection-file` | нет | Куда записать JSON с URL и токеном после старта. Права файла `0600` |
| `--server-url` | нет | Адрес Kraken Server. Включает режим воркера |
| `--server-token` | `KRAKEN_AGENT_TOKEN` | Машинный токен воркера |
| `--lease-seconds` | `60` | На сколько секунд воркер берёт задание |

Локальный запуск без сервера:

```powershell
uv run kraken-agent --plugins-config plugins.json
```

Воркер:

```powershell
uv run kraken-agent --server-url http://127.0.0.1:8080 --plugins-config plugins.json
```

Шаблон переменных: [`config/templates/agent.env.template`](../../config/templates/agent.env.template).
