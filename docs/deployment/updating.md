# Обновление Desktop и Server

Обновляйте приложение в окно обслуживания. Перед началом сохраните работу,
дождитесь завершения либо штатно отмените jobs, закройте Desktop и остановите
нужный экземпляр Server вместе с его Gateway/Agent. При работе через службу
Windows проверьте её ImagePath: он должен указывать на обновляемую установку.
Не останавливайте службу другой установки с таким же именем.

Установщики больше не закрывают приложения автоматически, в том числе с
`/VERYSILENT`. До замены файлов проверяются существующие EXE/DLL/PYD в каталоге
приложения. Занятый или недоступный файл даёт отказ с его путём в журнале.
Для тихой установки такой отказ на этапе подготовки имеет код 7; после
устранения причины повторите установку. Удаление занятого приложения также
отклоняется. Нельзя обходить отказ завершением процесса во время записи данных.

## Порядок действий

1. Сохраните проверенную согласованную копию PostgreSQL и всех настроенных
   файловых хранилищ. Для выпусков с `backup-server` используйте
   [инструкцию backup/recovery](../server-backup-recovery.md). Сохраните отдельно
   сведения о внешних путях, PKI и установленных плагинах.
2. Завершите приложения и jobs. Зафиксируйте путь конфигурации и путь
   установленного приложения. При обновлении сохраните ту же область
   установки (current user/all users) и тот же каталог.
3. Запустите доверенный установщик выбранного выпуска. При тихой установке
   проверяйте код завершения; только 0 означает успешное завершение. Не
   запускайте приложения параллельно с установщиком.
4. Для Server выполните **новым** `KrakenAdmin.exe migrate --config <server.toml>`
   перед возобновлением пользовательской работы. Не запускайте `init` или
   `bootstrap-admin` заново поверх существующего сервера. Конфигурация и
   защищённые секреты остаются в прежнем каталоге данных.
5. Запустите Server с прежней конфигурацией, затем Desktop. Проверьте вход
   существующим аккаунтом, проекты, историю, матрицу, старые версии файлов и
   скачивание. После обновления сделайте и проверьте новую резервную копию.

Каталог приложения предназначен для поставляемого runtime. Данные проектов,
файловые корни, конфигурацию и пользовательские настройки храните отдельно.
Обновление и удаление не должны использоваться как команда очистки данных.
В приёмке проверен также сохранённый непоставляемый файл в каталоге приложения.

## Сбой и откат

Если установка не завершилась успешно, оставьте приложения остановленными,
сохраните журнал и повторите установку того же пакета. Не используйте runtime
с частично заменёнными файлами. Установка не является атомарной сменой всего
каталога при физическом отказе диска/питания; такой сценарий пока не принят.
Проверка занятости — предварительная проверка, а не запрет запуска нового
процесса другим пользователем во время последующего копирования.

После миграций откат одних EXE не откатывает БД. Для восстановления прежнего
состояния используйте проверенную копию и отдельную пустую базу/новые каталоги;
не пытайтесь перезаписать активную базу старым dump.

## Что фактически проверено

На этой Windows-машине выполнено обновление отдельно идентифицированных audit
установок, с прежних настоящих EXE на текущие. Фикстурные номера установщиков
0.1.0 → 0.1.1 обозначают тест, а не опубликованный выпуск.

Server: отказ обновления при работающем сервере, замена после штатной остановки,
прежний аккаунт/конфигурация/история и 16 реальных JPEG/CIF пар, SHA/Range всех
32 файлов, migrations, backup обновлённого сервера и restore в новую базу.
Desktop: отказ замены занятой EXE, обновление после её завершения, вход прежним
локальным аккаунтом и открытие прежнего проекта новой EXE. Проверены 16 пар,
32 SHA, два прежних head versions, история, настоящие Qt cells/миниатюры,
неизменность канонических файлов и старых настроек. Дополнительно полный
Desktop self-test на реальных парах выполнен уже обновлённой EXE.
Служба Windows при этом не устанавливалась. Production AppId, повышенный SCM,
clean OS/reboot, физический power-cut и rollback произвольных миграций требуют
отдельной приёмки.
