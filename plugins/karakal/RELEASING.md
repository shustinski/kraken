# Как выпускать версии Каракала

## Один раз: папка обновлений

Впишите сетевую папку в `plugins/karakal/resources/update_client.json`, поле `update_root`:

```json
{
  "update_root": "//SERVER/share/karakal",
  ...
}
```

Пишите путь прямыми слэшами (`//SERVER/share/karakal`) — так не нужно удваивать `\` в JSON.
Windows понимает такой путь. Вариант с обратными слэшами: `"\\\\SERVER\\share\\karakal"`.

Этот путь:
- вшивается в каждую следующую сборку, и тестировщикам ничего не нужно настраивать;
- берётся скриптом публикации как место, куда класть сборки.

Внутри папки скрипт сам создаст `beta\` и `stable\`, в каждой `version.json` и установщики.
Выбрать папку в программе нельзя: тестировщик видит только «Канал», «Проверить обновления»
и «Что нового». Поэтому путь должен быть вписан до сборки, которую раздаёте.

Переезд папки: `.\publish.ps1 -MoveTo //NEW/share/karakal -ShareRoot //OLD/share/karakal`, затем
поменяйте `update_root`. Установленные программы сами перейдут на новый путь.

## Сборка дома, установка в офисе с флешки

Офисный путь можно не знать при сборке.

1. Дома публикуйте на флешку: `.\publish.ps1 -Channel beta -ShareRoot G:\KarakalUpdates`.
   Эта папка — главная копия: по ней считаются номера бет, не чистите её.
2. В офисе создайте сетевую папку (себе «Изменение», остальным «Чтение») и скопируйте флешку:
   `robocopy G:\KarakalUpdates \\ОФИС-ПК\Karakal /E`.
3. На каждой машине запустите установщик с флешки. На странице «Папка обновлений» впишите
   или выберите `\\ОФИС-ПК\Karakal`. Путь сохраняется в `settings.ini` рядом с программой
   и важнее пути из сборки. Без окон: `Karakal-setup-….exe /UPDATEROOT="\\ОФИС-ПК\Karakal"`.
4. Каждую новую версию: публикация на флешку дома → `robocopy` в офисе. Машины обновятся сами.

## Что писать в CHANGELOG.md

`plugins/karakal/CHANGELOG.md`, раздел «Не выпущено». Пункты — для тестировщика: что он увидит
и что изменилось в работе. При публикации раздел становится разделом версии и показывается
в окне «Доступна новая версия» и в меню «Обновление → Что нового…».

## Бета для тестировщиков

```powershell
cd plugins\karakal\scripts
.\publish.ps1 -Channel beta
```

Скрипт:
1. проверяет, что всё закоммичено и что в «Не выпущено» есть текст;
2. берёт номер из кода (`0.2.<алгоритм><интерфейс>`) и следующую свободную бету
   из папки обновлений: `-beta0`, `-beta1`, …;
3. запускает тесты, собирает exe и установщик;
4. кладёт установщик в `<папка>\beta\` и обновляет `version.json`;
5. переносит «Не выпущено» под номер версии, пишет номер беты в `version.py`;
6. кладёт копию в `G:\karakal_<версия>\` (установщик + `karakal_portable`), `-CopyRoot ""` — без копии;
7. коммитит `CHANGELOG.md` и `version.py` и ставит тег `karakal-v<версия>` (без push).

Тестировщики получат окно «Доступна новая версия» при следующем запуске.

Новый номер интерфейса или алгоритма (`INTERFACE_NUMBER` в `version.py`,
`GRID_ALGORITHM_NUMBER` в `core/algorithm_version.py`) — бета снова начинается с `-beta0`.

## Релиз (stable)

```powershell
.\publish.ps1 -Channel stable
```

Выпускает тот же номер без суффикса, например `0.2.9103`. Он новее любой `0.2.9103-betaN`.
В заметки релиза попадают все беты после прошлого релиза. Релиз кладётся и в канал beta,
чтобы тестировщики тоже его получили. После релиза следующей бете нужен новый номер
интерфейса или алгоритма — скрипт подскажет.

Пока релизный интерфейс не готов, stable собирается с интерфейсом тестировщика. Чтобы
переключить, в `publish.ps1` поменяйте `$ChannelProfiles = @{ beta = "tester"; stable = "tester" }`.

## Проверить, не публикуя

```powershell
.\publish.ps1 -Channel beta -DryRun
```

Пишет в `%TEMP%\karakal_share`, ничего не коммитит, `CHANGELOG.md` не меняет.
`-SkipBuild` — без сборки, `-SkipTests` — без тестов.
