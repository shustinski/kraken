векторизации в этом прогоне не запускаются. После исправлений пересобраны
Desktop/Server и проверены новые audit-установщики; предыдущие
`planning-final-installers` относятся к предшествующему коду.

## Причина и исправления

`frame_cells` выполнял отдельный запрос активной версии для каждой серии.
На реальном индексе SQLite без статистики планировщик выбирал
`SEARCH typed_current_models USING PRIMARY KEY (model_type=?)`, то есть
сканирование всех версий для каждого кадра. Существующий индекс родительской
серии давал точечное чтение. Матрица теперь использует пакетный метод:
не более 500 SQL-параметров в запросе, явный существующий индекс и один
connection для всех пакетов. Дедупликация идентификаторов ограничивает
повторную работу. Исторические запросы `as_of` сохраняют прежний путь.

Профиль после первого исправления обнаружил повторное декодирование всей
истории ради двух типов событий и многократное разрешение аннотаций каждого
экземпляра модели. Выбор событий теперь выполняется перед копированием и
декодированием; проверка канонического журнала остаётся до фильтрации.
Результаты по-прежнему являются независимыми копиями. Описания классов
кэшируются с лимитом 128; содержимое проекта в этот кэш не помещается.

Регрессии проверяют актуальный head после записи, координаты из родительской
версии, `in_review`, confidence, историческое состояние, более 1100 запрошенных
серий при SQL-лимите 500, изоляцию возвращаемых событий и отказ при повреждении
сегмента, который не содержит выбранного типа события.

Прицельный итог: 45 passed, 1 skipped (настоящий POSIX fork на Windows).
Исходная ошибка нового теста сохранена в `viewport-batched/scoped-tests.xml`:
он ожидал состояние issued сразу после создания draft review batch. Fixture
исправлен фактической выдачей пакета; успешный повтор сохранён отдельно.

Общий последующий root gate `production-audit-20261027/viewport-final-root/summary.json`:
192 модуля, 1237 cases, 0 failures/errors, 90 skipped, 1147 выполнены.
PostgreSQL в этом прогоне не включён. Причины пропусков сохранены в
`skipped-tests.json`: отдельные live/PG/training/E2E gate, POSIX fork и
недоступное создание symlink. Пропуски не засчитываются как выполненные.
Полной фиксации исходников до/после этого прогона не было; SHA восьми
изменённых source/test файлов сохранены отдельно. Во время прогона удалён
неиспользуемый импорт `Path` из теста; production sources не менялись.
Предыдущий PostgreSQL gate относится к предыдущему состоянию исходников и
не заменяет этот результат. Scoped Ruff и проверка whitespace пройдены.

## Свежие малый и средний импорты

Из того же manifest выделены первые 16 и 256 пар. Созданы отдельные новые
audit-проекты в рабочем каталоге; исходные каталоги не изменялись. Импорт
выполнен через настоящий `materialize_reference_project.py` и
`commit_managed_import`; затем `verify_reference_project.py` повторно проверил
все исходные файлы, blob, квитанции, версии и канонический журнал.

| Пары | Исходные байты | Импорт с созданием проекта, с | Проверка, с | Первый viewport, с | Повторы, с |
| ---: | ---: | ---: | ---: | ---: | --- |
| 16 | 33 295 580 | 5,188 | 0,569 | 0,099 | 0,088; 0,083 |
| 256 | 390 900 836 | 72,202 | 2,151 | 0,340 | 0,171; 0,172 |

Здесь viewport — строка из 16 ячеек, оба представления; SHA каждой ячейки
сверен с manifest. Это другой размер viewport, поэтому его время не следует
непосредственно делить на результат полного корпуса. Во время импорта мог
выполняться общий root gate; результаты описывают эту машину и эту нагрузку.
Примерный максимум суммы RSS дерева импортёра, наблюдаемый каждые 100 мс:
62 820 352 и 63 033 344 байт. Это sampled RSS, не строгий пик памяти ОС.

Полные квитанции и воспроизводящий скрипт:
`production-audit-20261027/reference-load/{probe.py,report.json}`;
проверки целостности — `reference-load/integrity-{16,256}/report.json`.
Оба проекта сохранены для последующих проверок, обучение не выполнялось.

## Оставшиеся ограничения

Матрица всё ещё собирает полное представление до фильтрации viewport; её
стоимость зависит от размера проекта. 2,3 секунды на повторный запрос не
закрывают интерактивный performance gate. Пространственные запросы, многослойные
крупные проекты, конкурентные пользователи, сетевой сервер, долгий профиль
памяти, снимки миниатюр и реальные действия GUI требуют отдельных измерений.
Свежий полный импорт, чистая ОС/SCM, обновление production installation и
полный установленный UI-сценарий также остаются открытыми. Полная готовность
системы этим протоколом не объявляется.
