# Обмен сшитой геометрией слоя

Принятую векторную мозаику можно открыть в просмотре блоков и сохранить
кнопкой «Экспортировать векторы…». В удалённом проекте скачиваются векторные
блоки; полный файл мозаики с изображениями не скачивается. Экспорт читает
закреплённый результат и не запускает Contour, обучение или новую сшивку.

Файл `*.jsonl` использует schema `kraken.layer-vectors.v1`. Это инженерные
локальные координаты, **не географический GeoJSON**. Геометрические объекты
имеют структуру Polygon/MultiPolygon с наружными кольцами и отверстиями.
Первая строка — header: project/layer/job/output version, SHA исходной
мозаики и geometry plan, reference calibration, grid и исходные CIF versions.
Далее следует по одной строке на каждый блок, включая пустые блоки, в порядке
row-major. Последняя строка — seal с числом блоков и SHA-256 точных UTF-8
байтов всех предыдущих строк, включая завершающий LF каждой строки.

Каждый feature и conflict содержит:

- `geometry`: точные координаты исходного mosaic block в общих опорных пикселях;
- `geometry_m`: те же кольца после reference calibration, в метрах;
- `category` и `source_version_ids`; у conflict также обе `frame_ids`.

Новые файлы также сохраняют `coverage_semantics=sampled_reference_pixel_centres`
в header и сжатую uint32-le маску `coverage` в каждом блоке. Ноль означает
отсутствие измеренного покрытия в центре пикселя; положительное значение —
число покрывающих кадров. Отсутствие контура вне покрытия нельзя трактовать
как пустой измеренный фон. Маска проверяется по размеру, SHA, zlib stream и
максимальному числу исходных кадров. `reader.coverage(record)` возвращает
проверенные uint32-le bytes. Для раннего v1 файла без coverage возвращается
None: всё покрытие неизвестно, а не заполнено нулями или единицами.

X переводится как `origin_x + x * pixel_size_x`. Для Y используется плюс при
`y_axis=up` и минус при `y_axis=down`. Калибровка, её revision, artifact anchor
и uncertainty сохраняются в header. Целочисленное квантование не применяется.
Фрагменты соседних блоков находятся в общей системе координат; их общая
граница не является разрывом исходной геометрии или отдельным электрическим
контактом. Геометрический потребитель может объединять фрагменты одной
категории. Provenance и conflicts при этом необходимо сохранять отдельно.

Проверка завершённости обязательна перед приёмкой файла. Библиотечный
`VectorExchangeReader.blocks()` выдаёт проверенные записи по одной, а
`reader.verified` становится true только после полной проверки seal, числа
блоков, provenance, bounds и соответствия геометрии в метрах калибровке.
Прерванный итератор или отсутствующий seal не подтверждает полный результат.
Число объектов в отчёте относится к фрагментам блоков, не к числу проводников.

Экспорт пишет временный файл и публикует новое имя после повторного полного
чтения. Существующий файл не перезаписывается. Отмена, сбой сети, смена
идентичности источника или превышение бюджета не публикуют неполный файл.
В Windows применяется rename без замены существующего назначения; на POSIX
— exclusive hard link. Политика POSIX требует файловую систему с hard links;
Linux/macOS installed gate остаётся отдельной проверкой.

CLI из рабочего checkout:

```powershell
.venv/Scripts/python.exe tools/stitch_vector_exchange.py export --data-dir <data> --project-id <uuid> --job-id <uuid> --output vectors.jsonl
.venv/Scripts/python.exe tools/stitch_vector_exchange.py verify vectors.jsonl
```

Project-authorized read API:

- `GET /api/v1/projects/{project}/stitch-renders/{job}/vectors` — header;
- `GET /api/v1/projects/{project}/stitch-renders/{job}/vector-blocks/{column}/{row}` — один bounded block в опорных пикселях с закреплённой output identity.

Header и каждый блок принадлежат одному неизменному job/output version/SHA.
Remote exporter дополнительно вычисляет SI geometry и проверяет этот контракт
перед записью. API использует прежний project reader access; export не даёт
права изменять проект. Электрическая связность и физическая точность этим
форматом не подтверждаются. Это формат геометрического обмена, не EDIF/netlist
и не готовая интеграция всех внешних редакторов.
